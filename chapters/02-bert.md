# BERT：从双向理解，到通用语言表示

论文：BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding（2018）

## 01 · 理解一个词，要看两边

这篇就是著名的 BERT 论文：《BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding》。如果用费曼法来读，我们先把 Transformer、embedding、attention 这些术语全部放到一边，只问作者一个最朴素的问题：**一个模型想真正理解一句话里的某个词，应该只看这个词前面发生了什么，还是应该同时看前面和后面？** BERT 的答案很简单：当然应该两边一起看。比如一句话：“我去银行存了钱。”这里的“银行”很容易理解成金融机构；但如果一句话是“我坐在河流的银行旁边”这种英文 bank 的语境，你必须看到周围所有词，才能确定 bank 到底是什么意思。BERT 这篇论文最核心的贡献，就是找到了一种办法，让一个深层 Transformer 在预训练阶段真正同时利用左右两边的上下文，从而学出更好的语言表示。

## 02 · 单向语言模型的限制

要理解 BERT 为什么在 2018 年那么重要，得先看看它之前的人怎么训练语言模型。当时一个很自然的方法是：给模型一句话，让它根据前面的词猜后面的词。例如“我今天去超市买了一个____”，模型从左往右猜“苹果”。这种训练有一个很大的优点：任务可以自动生成，你根本不需要人工标注，只要有大量文字，就有无限训练题。但缺点也明显：模型在理解“苹果”时，只能看到左边的“我今天去超市买了一个”，不能看到右边后续的话。如果后面其实是“手机”，那么完整句子可能是“我今天去超市旁边的店买了一个苹果手机”，后面的信息显然会改变“苹果”的含义。早期 GPT 就属于这种左到右的思路，每个位置只能注意到它左边的 token。BERT 的作者认为，这种单向限制对于“理解语言”尤其不合理，特别是问答、自然语言推理、命名实体识别这类任务，因为判断一个词究竟是什么意思，经常需要它两边的信息。

## 03 · 把答案遮住：MLM

可是这里马上出现一个麻烦：如果你允许模型同时看左右两边，再让它预测一个词，那答案不是直接泄露了吗？比如训练题是“我喜欢吃苹果”，你要求模型预测“苹果”，同时又允许它看完整句子，那它当然知道答案是苹果，因为“苹果”自己就在输入里。这就像考试时把答案印在试卷旁边。BERT 最聪明的一步，就是想出了一个其实非常朴素的解决方法：**把答案遮住。**例如把“我喜欢吃苹果”变成“我喜欢吃 [MASK]”，然后让模型根据“我、喜欢、吃”以及后面可能出现的其他文字，把被遮住的词猜回来。这就是 Masked Language Model，简称 MLM。论文训练时随机挑出约 15% 的 WordPiece token 作为预测目标。这样模型在猜某个被遮住的词时，就可以同时使用它左边和右边的信息，于是深层网络里的每一层都能够建立真正的双向上下文表示。

你可以把这种训练想象成一本“完形填空大全”。比如给一个学生看：“小明因为没带伞，所以回到家以后衣服全都 ___ 了。”如果只能从左往右读，看到空格就必须立刻作答；而 BERT 可以把整句话先读完，再回答这个空格，所以它更容易猜出“湿”。更重要的是，如果这样做的题足够多，学生得到的不只是“湿”这个答案，而是逐渐学会了很多更抽象的知识：什么词经常搭配，代词通常指谁，一句话在表达因果还是转折，一段话中哪些词属于同一个实体，什么样的句子在语义上相似。**所以 MLM 真正的目的并不是训练一个特别会做完形填空的机器，而是用完形填空逼它学习语言内部的结构。**这就是理解 BERT 的第一把钥匙。

## 04 · 判断两句话的关系：NSP

但作者觉得，只会理解单句里的词还不够，因为很多 NLP 任务需要理解“两段文字之间是什么关系”。例如问答里有“问题”和“文章”，自然语言推理里有“前提”和“假设”。于是 BERT 又加入了第二个预训练任务，叫 Next Sentence Prediction，也就是 NSP。玩法是给模型两个句子 A 和 B，一半的时候 B 真的是 A 后面紧接着的句子，一半的时候 B 是从其他地方随机抽来的，然后让模型判断“B 真的是下一句吗？”比如 A 是“Tom 打开了冰箱。”B 是“他拿出了一瓶牛奶。”很可能是 IsNext；如果 B 是“地球距离太阳大约 1.5 亿公里”，大概率是 NotNext。论文里的训练样本正好是 50% 真下一句，50% 随机句子。作者希望通过这个任务，让模型不仅理解单词，也开始理解两个文本片段之间的关系。

所以 BERT 的预训练可以极度压缩成两道家庭作业：**第一道，把一些词遮住，让你猜；第二道，给两段话，让你判断它们是不是连续的。**而这一切都不需要人工标注。作者拿 BooksCorpus 大约 8 亿词，以及英文 Wikipedia 大约 25 亿词来训练，Wikipedia 只保留正文，去掉列表、表格和标题；他们还特别强调要保留文档级连续文本，因为 NSP 需要知道哪些句子本来属于同一个上下文。 这就是所谓 pre-training：先别管以后到底要让模型做情感分类、问答还是实体识别，先让它读大量文字，把语言练熟。

## 05 · BERT 的名字与结构

这时候我们才能真正理解“BERT”这个名字。BERT 是 Bidirectional Encoder Representations from Transformers。Bidirectional 就是“双向”；Encoder 表示它采用 Transformer 的编码器部分，目的主要是理解输入，而不是像 GPT 那样一个词一个词往后生成；Representations 则是说它最终想学到的是一套好的“语言表示”。BERT Base 有 12 层 Transformer、隐藏维度 768、12 个注意力头，大约 1.1 亿参数；BERT Large 则有 24 层、隐藏维度 1024、16 个注意力头，大约 3.4 亿参数。作者刻意让 BERT Base 的规模和当时的 OpenAI GPT 接近，这样比较起来更公平，而两者最关键的架构差异之一就是：BERT 的 self-attention 可以同时看左右两边，GPT 的每个 token 只能看左边。

## 06 · 从预训练到微调

然后论文进入第二个真正改变 NLP 的思想：**预训练一个模型，然后让所有具体任务都来“改造”这个模型，而不是每个任务从头造一个复杂系统。**以前做 NLP 很像做很多不同机器。情感分类设计一套网络，问答设计一套网络，实体识别又设计一套网络，工程师要针对任务手工设计大量结构。BERT 的想法更像先培养一个受过完整语言教育的“通才”，然后不同工作只做一次短期培训。这个短期培训就是 fine-tuning。预训练结束以后，如果要做情感分类，就给 BERT 加一个很薄的分类层，再用少量有标签的数据继续训练；要做问答，就让它预测答案在文章里的起点和终点；要做命名实体识别，就给每个 token 预测一个标签。主体几乎还是同一个 BERT，而且 fine-tuning 时整个 BERT 的参数都会跟着更新。

## 07 · 输入中的三个线索

这里还有几个今天看起来普通、当时却很巧妙的设计。每段输入开头都放一个特殊 token，叫 `[CLS]`。你可以把它想象成一个“总结位”。所有词通过 self-attention 相互交流之后，作者用最终的 `[CLS]` 向量当作整段文字的综合表示，所以如果任务是“这条评论是正面还是负面”，就拿 `[CLS]` 去做分类。另外两个句子之间放一个 `[SEP]`，相当于告诉模型：“这里第一段结束，第二段开始。”每个 token 的输入还不是只有“这个词是谁”，而是三个信息加在一起：token embedding 告诉模型“你是什么词”，position embedding 告诉模型“你在第几个位置”，segment embedding 告诉模型“你属于句子 A 还是句子 B”。这三部分加起来，再送进 Transformer。

## 08 · 遮盖背后的 80 / 10 / 10

MLM 里面还有一个特别值得读的细节，因为它体现了作者对“训练和真实使用不一致”的警觉。如果选中的 15% token 全部直接替换成 `[MASK]`，会有一个问题：实际 fine-tuning 的时候，文本里根本没有 `[MASK]`，所以模型训练时天天见 `[MASK]`，工作时却永远见不到它。作者于是做了一个小技巧：在被选中预测的 token 中，80% 替换成 `[MASK]`，10% 换成一个随机词，另外 10% 干脆保持原词不变，但不管表面怎么处理，模型都要预测原来的正确 token。 例如原来是“我喜欢吃苹果”，如果“苹果”被选中，有时看到的是“我喜欢吃 [MASK]”，有时可能是“我喜欢吃汽车”，有时仍然看到“我喜欢吃苹果”，但训练目标始终是苹果。这样做的目的，是让模型不要过度依赖 `[MASK]` 这种训练时的人造符号。

## 09 · 实验：双向理解有效吗？

接着来看实验，真正重要的不是记住所有 benchmark，而是问：**作者凭什么说这种做法有效？**他们在 11 个 NLP 任务上测试 BERT，包括 GLUE、SQuAD 问答、SWAG 常识推理等。当时结果非常夸张：论文摘要里报告 GLUE 分数达到 80.5，比此前提高 7.7 个绝对百分点；MultiNLI 准确率达到 86.7%；SQuAD v1.1 的 Test F1 达到 93.2；SQuAD v2.0 的 Test F1 达到 83.1。 在论文自己的 GLUE 表格里，BERT Large 在大多数任务上都明显超过 OpenAI GPT；例如 MNLI matched 从 GPT 的 82.1 提升到 86.7，RTE 从 56.0 提升到 70.1。 这说明“先进行大规模双向预训练，再对具体任务微调”不是只对某一种任务有用，而是一套相当通用的方法。

问答任务尤其能说明双向理解为什么重要。想象文章里有一句：“乔布斯于 1976 年和沃兹尼亚克一起创立了苹果公司。”问题是：“苹果公司是哪一年创立的？”BERT 会把问题和文章一起输入，然后给文章中每个 token 一个“成为答案起点”的分数，再给每个 token 一个“成为答案终点”的分数，最后找出最合理的一段，也就是“1976 年”。这件事要求模型同时理解问题、整篇文章，以及每个词前后的关系。BERT Large 在 SQuAD 1.1 上甚至单模型就能和当时的复杂 ensemble 系统竞争；加入额外 TriviaQA 微调后，论文报告测试 F1 达到 91.8，ensemble 达到 93.2。 这非常符合作者最初的直觉：对 token 级任务而言，一个词能够看到左右完整上下文是非常重要的。

## 10 · 拆零件，寻找有效的原因

但真正让我觉得这篇论文“严谨”的地方不是排行榜，而是它做了 ablation study，也就是拆零件实验。就像你造了一辆车，说它为什么快，不能只说“我加了很多新技术”，还应该把零件一个一个拆掉，看性能到底掉不掉。作者先去掉 NSP，只保留双向 MLM，结果一些任务性能下降；然后把双向 MLM 改成传统的左到右语言模型，并且去掉 NSP，表现进一步下降。在 SQuAD 上尤其明显：完整 BERT Base 是 88.5 F1，去掉 NSP 是 87.9，而改成左到右以后只剩 77.8。作者甚至又在左到右模型上加一个 BiLSTM，希望临时补回双向信息，SQuAD 上能回升到 84.9，却还是明显低于真正从预训练阶段就进行深度双向学习的 BERT。 所以作者想证明的是：不是“Transformer 随便做大一点就赢了”，**预训练阶段本身的双向性确实是重要原因。**

## 11 · 大模型与小数据集

另一个特别有意思的发现，是模型越大越好。作者从较小模型一路做到 24 层的 BERT Large，发现测试的几个下游任务几乎都随着模型规模增大持续改善。比如 MNLI 从一个 3 层模型的 77.9，提高到 BERT Large 附近的 86.6；SST-2 从 88.4 到 93.7。更值得注意的是，MRPC 这种只有约 3600 个训练样本的小任务也从更大的预训练模型中获得明显收益。作者因此提出一个当时很重要的观察：**只要预训练做得足够好，大模型即使面对很小的下游数据集，也可能比小模型表现更好。** 你如果刚刚读完 GPT-3，再回来看这里，会发现一条历史线已经开始出现了：BERT 时代已经在告诉大家，“规模 + 大规模预训练”可能是一条非常强的路线；后来 GPT-2、GPT-3 只是把这个规律推到了更加极端的规模。

## 12 · BERT 与 GPT-3：两种迁移方式

现在我们可以比较你刚才读的 GPT-3 和这篇 BERT。它们都相信同一件事：**先在海量无标注文本上学通用语言能力，再迁移到具体任务。**但它们在“迁移”的方式上非常不同。BERT 的世界观是：先预训练一个通才，然后每碰到一个新任务，都拿这个通才去 fine-tune，参数会改变。所以你会得到“情感分类版 BERT”“问答版 BERT”“NER 版 BERT”。GPT-3 的世界观则进一步走了一步：最好连 fine-tuning 都不要，直接把任务说明和几个例子写进上下文，模型参数完全不动。可以把历史路线非常粗略地记成：**BERT 问的是“能不能训练一个通用大脑，然后快速培训它去做不同工作？”GPT-3 问的是“这个大脑能不能强到连培训都省掉，只要当场把工作说明给它看就会做？”**这就是从 pretrain + fine-tune，逐渐走向 pretrain + prompt / in-context learning。

## 13 · 读者与作家

BERT 和 GPT 的另一个根本区别，可以用“读者”和“作家”来理解。BERT 更像一个非常擅长读文章的人：你把整篇文章摆在他面前，他可以前后翻看，然后判断这句话什么意思、答案在哪里、这段话是什么情绪。GPT 更像一个写作者：它不断根据已经写下来的东西决定下一个词应该是什么，所以天然适合继续生成文本。BERT 使用 Transformer encoder，所有位置可以互相注意；传统 GPT 使用 causal mask，让每个位置只能看到以前的 token。于是 BERT 天然特别适合理解任务，而 GPT 天然特别适合生成任务。当然，这并不是说 GPT 不能理解——后来大规模生成模型已经证明，仅靠 next-token prediction 也能形成很强的理解能力——但在 2018 年 BERT 的设计逻辑里，这个区别非常关键。

## 14 · 真正的深度双向

这里也有一个容易产生的误解：**BERT 的“Bidirectional”不等于它从左到右读一遍，再从右到左读一遍。**那更接近 ELMo 的做法。ELMo 会训练一个左到右语言模型，再训练一个右到左语言模型，最后把两边的表示拼起来。BERT 更激进：它在 Transformer 的每一层里，同一个 token 就能直接同时关注左边和右边。因此作者把它称为“deep bidirectional”。在论文的解释里，这比最后才把两个方向拼起来更强，因为左右上下文可以从底层开始就不断互动。 这也是 BERT 真正值得记住的技术贡献之一。

## 15 · 后来的改进与启发

不过如果站在今天回头看 BERT，也要知道论文中的一些东西后来被证明并不是不可替代。例如 NSP 当时被论文的消融实验认为有帮助，但后来 RoBERTa 等工作发现，用更好的训练策略、更多数据训练时，可以去掉原版 NSP 仍然取得更好的表现。所以不要把 BERT 理解成“MLM + NSP 是自然语言理解的终极公式”。更准确的历史理解是：**BERT 证明了深度双向自监督预训练 + 下游微调这一整套范式极其有效。**至于具体应该怎么 mask、要不要 NSP、训练多少数据、训练多久，后来还有大量论文继续改进。

## 16 · 用一分钟讲给朋友听

如果现在把整篇论文合上，用一分钟向一个完全不懂 AI 的朋友解释，我会这样讲：**以前做自然语言处理，很像每一种工作都单独培养一个专家，而且语言模型通常只能从左往右读。BERT 的作者认为，真正理解语言应该同时利用一个词前面和后面的内容。可是如果训练时让模型直接看到完整句子，它又会偷看答案，所以他们随机把一些词遮住，让模型根据左右文把它猜回来；同时再让模型判断两句话是不是相邻。通过在几十亿词上做这种“完形填空”和“句子关系判断”，BERT 先学会一种通用的语言理解能力。之后面对分类、问答、推理、实体识别等任务，只需要加很少的任务专用结构，再用有标签数据微调，就能取得当时最好的成绩。**

所以如果只允许你从这篇论文里带走三个真正能用很多年的概念，我会把它们压成一句话：**Masking 让双向学习成为可能，Pre-training 学通用语言表示，Fine-tuning 把通用能力变成具体能力。**而如果把它和你上一章 GPT-3 连起来读，整条路线就更清楚了：**BERT 证明“一个预训练模型可以成为许多任务的共同起点”；GPT-3 又继续追问“既然起点已经越来越强，能不能连针对任务改参数这一步也省掉？”**📖 这两篇放在一起读，其实正好能看见现代大语言模型范式是怎样一步步长出来的。
