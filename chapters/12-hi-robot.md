# Hi Robot：在行动中持续理解人类意图

论文：Hi Robot: Open-Ended Instruction Following with Hierarchical Vision-Language-Action Models（2025）

## 01 · 从会动作到听懂复杂要求

这篇是《Hi Robot: Open-Ended Instruction Following with Hierarchical Vision-Language-Action Models》。如果你刚刚读完 π0 和 FAST，这一篇其实非常顺，因为它不再主要解决“机器人怎么把手动起来”，而是在问一个更上一层的问题：**机器人已经会抓、放、移动、折叠这些动作以后，怎样才能真正听懂人类那些复杂、含糊、会临时改变的要求？**比如“帮我做一个素食三明治，我不喜欢番茄”“把桌上的垃圾清掉，但盘子别动”“帮我拿点适合电影夜吃的东西”，甚至机器人已经抓起一个碗时，你突然说一句“那个不是垃圾”。这类任务和“拿起红色杯子”完全不是一个难度，因为机器人不仅要有动作技能，还要理解人的意图、当前环境、之前做过什么，以及一句反馈到底是在指眼前哪个东西。Hi Robot 的核心答案是：**不要强迫一个模型同时负责‘想清楚做什么’和‘把手精确地动起来’，而是把两件事分成高层和低层。高层负责思考和对话，低层负责执行动作。**作者把它类比成 System 2 和 System 1：一个慢一点、负责推理，一个快一点、负责熟练动作。([arXiv][1])

## 02 · 高层规划，低层执行

先用费曼法想象一个真正的人类助手。你告诉他：“把餐桌收拾一下，但是那个人还没吃完，所以别拿他的盘子。”你不会期待他的大脑直接把这句话变成“右肩关节旋转 0.013 度”。人脑首先会形成一个更简单的当前目标，比如：“先拿走这个空纸杯”“这个盘子暂时别碰”。等这个小目标确定以后，身体运动系统才负责手伸多远、手指什么时候闭合。Hi Robot 基本就是把这个结构显式做出来。高层 policy 看摄像头画面和用户的复杂语言，然后输出一个简单的低层命令，例如“pick up the paper cup”；低层 policy 再看画面、机器人关节状态和这个简单命令，输出真正的连续动作。高层不是每几十毫秒运行一次，而是较慢地更新；论文的实现很简单：**大约每 1 秒重新跑一次高层，或者用户一说新话就立即重新规划。**低层则持续高频执行动作。([arXiv][1])

所以整个系统可以压缩成一个非常容易记的链条：**复杂用户意图 → 高层语言命令 → π0 → 机器人动作。**比如用户说：“给我拿点甜的东西。”高层模型先看货架，发现有 KitKat、Skittles，也许还有饮料，于是根据语义和当前画面输出“pick up KitKat”；π0 根本不需要理解“适合甜食”的抽象概念，它只需要完成自己已经很擅长的原子任务：“把 KitKat 拿起来。”这就是 hierarchy 的力量：**抽象问题在抽象层解决，运动问题在运动层解决。**如果把“甜的”“素食”“只收黄色东西”“不要泡菜”这些高层约束全塞给动作模型，让它从一句复杂自然语言直接映射到几十维连续关节动作，相当于要求运动皮层同时承担语言推理，学习难度会大很多。([arXiv][1])

## 03 · 同一个视觉语言起点，两种专业训练

而且这篇论文不是随便找一个规则程序做底层，它直接建立在你上一章读过的 **π0** 上。高层和低层一开始都来自同一个 PaliGemma-3B 视觉语言模型。高层把 PaliGemma fine-tune 成“看图 + 听复杂要求 → 输出下一条简单机器人命令”的模型；低层则是 π0，也就是给 PaliGemma 加上 flow-matching action expert，让它把简单语言命令转成连续 robot action chunks。([arXiv][1]) 所以很有意思：Hi Robot 的“思考脑”和“运动脑”祖先其实几乎是同一个 VLM，只是后来接受了不同专业训练。一个毕业以后变成 planner，一个毕业以后变成 controller。

## 04 · 从正确技能反向生成用户指令

这里马上出现这篇论文真正困难的地方：**高层模型的训练数据从哪里来？**低层很好理解，人在现场遥控机器人做一次“拿起生菜”，摄像头、关节状态、动作全都记录下来，就得到机器人示范。但你不可能请人再把所有可能的用户表达都演一遍。现实中的人可能说“加点绿色的东西吧”“我要素食”“不要肉”“我对火腿过敏”“放点生菜进去”“那个我不吃”，实际上都可能对应同一个底层动作“pick up lettuce”。如果靠人类把这些表达全部标注，数据成本会非常高，而且永远覆盖不完开放语言。作者于是用了一个很漂亮的办法：**反过来生成问题。**他们已经知道某个画面里正确的小技能是“pick up lettuce”，就把当前机器人画面和这个技能交给一个强 VLM，然后问它：“请想象一下，用户在什么情况下会说什么话，才会导致机器人现在应该拿生菜？”于是模型可能生成“Can you make me a vegetarian sandwich?”、“Could you add something green?”之类的合成用户指令，再生成机器人可能说的确认或澄清。([arXiv][1])

这一步特别值得理解，因为它不是普通的“让大模型随便写点合成数据”。它生成的是 **situated synthetic data，也就是有场景约束的合成数据**。生成模型既看到了“机器人现在看到什么”，又知道“最终应该触发哪项物理技能”。所以它不能随便幻想一个和现实无关的 prompt，而是在倒推：**在这个现实场景里，什么样的用户语言会合理地导致这个动作？**例如眼前货架有 KitKat，目标技能是“pick up KitKat”，模型可能生成“给我拿点甜的”；如果桌上一个碗被误认为垃圾，模型可以生成“那个不是垃圾”。这样，一小批真实机器人动作示范就能扩展出大量复杂、组合式、自然的人类表达。作者随后用真实 skill labels 加这些 synthetic interactions 一起训练高层模型。([arXiv][1])

## 05 · 两个层级，两种训练目标

所以 Hi Robot 的训练其实有两个完全不同的监督信号。高层模型学的是标准 **next-token prediction**：给图片和用户语言，预测应该说什么或者下一个低层 skill label 是什么；低层 π0 学的仍然是你已经熟悉的 **flow matching**：根据图片、机器人状态和简单语言命令生成连续动作。([arXiv][1]) 这非常有意思，因为同一个机器人系统里同时存在两种生成世界：**离散语言适合 autoregressive token prediction，连续动作适合 flow matching。**高层把世界压缩成“下一步该做什么”的语言，低层再把这句话展开成几百毫秒甚至几秒的运动。

## 06 · 开放语言如何改变长程决策

这也解释了为什么论文题目叫 **Open-Ended Instruction Following**。过去很多 VLA 已经能执行“pick up the cup”“put the banana in the bowl”，但这种语言本质上只是给动作技能起了个名字。Hi Robot 想处理的是开放语言，比如“清掉垃圾但不要动餐具”。这句话不只是指定某个技能，它隐含一个**规则**：接下来看到每个物体，都要判断它是不是垃圾；是垃圾才拿，不是就跳过。所以机器人每做完一步，都需要重新看当前世界和原始目标，再决定下一步。如果用户中途说“leave the rest”，目标又立即改变。论文强调的正是这个区别：普通 VLA 更像“语言触发技能”，Hi Robot 则想让语言真正影响任务的**长程决策过程**。([arXiv][1])

## 07 · 三种任务与三种机器人

论文测试了三个很生活化但其实相当困难的场景。第一个是 **Table Bussing**，也就是清理餐桌。机器人不只是把所有东西扔掉，而可能被要求“只收垃圾”“只收餐具”“只收偏黄色的东西”，中途还可能被纠正“那个不是垃圾”。有些动作本身也相当灵巧，例如抓盘子边缘，或者先拿起装着垃圾的盘子，再倾斜盘子把垃圾倒进垃圾桶。第二个是 **Sandwich Making**，机器人需要操作面包、奶酪、生菜、肉片等柔软或易损物体，同时理解“做素食的”“不要泡菜”“加芝士、烤牛肉和生菜”这类组合约束。第三个是 **Grocery Shopping**，双臂移动机器人在货架前根据“给电影夜拿点薯片”“给我一些甜的”“我要喝的”这样的语义要求选择商品，中途用户还可能补一句“再给我一块 KitKat”。([arXiv][1])

尤其值得注意的是，这三个任务用了**三种机器人形态**：单机械臂、双机械臂，以及带移动底盘的双臂机器人。([arXiv][2]) 这再次延续了 π0 的 generalist 思路：作者不是在展示一个精心针对某台机器写死的 task planner，而是在测试同样的“高层 VLM → 语言接口 → 低层 VLA”结构能不能跨 embodiment 工作。因为高层和低层之间的协议是语言，例如“pick up KitKat”，而不是某台机器专属的关节指令，所以这种层级天然具有一定模块化：换底层机器人时，高层推理逻辑原则上不用完全重写。

## 08 · 通用知识不等于具身经验

作者拿它和一个很有意思的 baseline 做比较：直接用 **GPT-4o 当高层 planner**，下面仍然接同一个 π0。直觉上你可能会觉得 GPT-4o 规模更大、语言和视觉能力更强，应该直接赢。但实验反而显示 Hi Robot 的 instruction accuracy 平均比 GPT-4o baseline 高 **40% 以上**。([arXiv][1]) 原因特别值得琢磨：**通用 VLM 很聪明，不等于它了解这具机器人的“身体世界”。**GPT-4o 有时候会识别错具体物体、漏掉中间步骤，甚至论文记录到类似“pick up bermuda triangle”这种明显脱离物理场景的命令；还会出现夹爪手里已经有东西，却让机器人再抓另一个东西的情况。([arXiv][1])

这其实揭示了 embodied AI 一个很重要的规律：**世界知识 ≠ 具身 grounding。**一个通用 VLM可能非常会解释图片，但它没有长期在“这个摄像头角度、这台机械臂、这些技能、这种任务进度”上被训练过。所以它知道“盘子是什么”，却未必知道“π0 此刻最可靠的下一项动作是什么”。Hi Robot 的高层虽然也是一个相对小的 PaliGemma-3B 起步，但经过真实机器人 observation + skill labels + situated synthetic interactions 训练以后，它学到了一种很特殊的知识：**什么是这个身体现在能做、该做、做得好的事情。**所以“更大的通用模型”并没有自动胜过“更小但被真实身体经验 ground 过的模型”。

## 09 · 层级结构本身的价值

作者还做了另一个非常关键的比较：不用高层，直接让一个 **flat π0 VLA** 接受复杂用户指令。结果层级结构总体更好。为了排除“是不是 Hi Robot 只是因为看了更多 synthetic data”的解释，他们甚至让 flat VLA 也吃同一套 synthetic prompts，再比较。层级版本依然更擅长处理中途反馈和复杂约束。([arXiv][1]) 这个实验在逻辑上非常重要，因为它说明**hierarchy 本身有价值，而不只是多了训练数据。**一个 flat policy 即使知道“只收黄色东西”这句话，执行几十步以后也更容易重新滑回训练数据里的默认行为——比如把桌上所有东西都清理掉；高层模型则每隔一小段时间重新看原始 prompt 和当前场景，再生成下一条简单命令，相当于不断提醒自己：“我的总目标到底是什么？”

可以把两者比成做饭。Flat policy 像你把“做一个素食三明治，不要泡菜”这句话告诉一个厨师一次，然后让他连续忙十分钟；训练习惯可能让他顺手又拿起火腿。Hierarchy 则像旁边有一个主厨每隔一会重新看订单，再告诉助手：“现在拿一片面包”“现在加生菜”“不要拿火腿”。低层助手不需要记住完整复杂要求，只要准确执行眼前这一小步。**Hierarchy 本质上是在降低每个决策层需要处理的时间尺度和抽象跨度。**

## 10 · 合成数据扩展语言空间

合成数据的消融实验也很有说服力。去掉 synthetic interaction data 后，高层模型仍然能看图、也会输出合理的基本 skill，但面对“这个不是垃圾”“不要泡菜”这种偏离默认任务的特殊条件时，明显更容易忽略用户约束。加入合成数据后，它才能稳定处理更多组合式语言和实时反馈。([arXiv][1]) 这说明真实 robot demonstrations 解决的是 **“机器人会做哪些事情”**，但它并不能自动覆盖 **“人可能用多少种方式要求这些事情”**。语言空间远远比机器人技能空间大：100 个物理技能可能对应几万种自然语言表达。因此这里用生成模型扩展语言侧的数据，是一个很自然的 data scaling 方法。

## 11 · 实时反馈与情境推理

实时反馈是这篇论文另一个特别重要的部分。假设机器人正在把一个碗往垃圾箱搬，你说：“that’s not trash。”这句话本身信息非常少。如果只把它输入语言模型，根本不知道 “that” 指什么。Hi Robot 的高层同时看到当前摄像头，因此知道机器人现在正拿着哪个物体，于是能够把“that”绑定到眼前的碗，停止原计划，甚至把它放回去。论文把这种能力称为 **situated reasoning**：语言的意思依赖于当前物理状态。([arXiv][1]) 这正是机器人和纯聊天模型最大的区别之一——“它”“那个”“这里”“再来一个”“不要这个”这种人类日常语言，只有结合共同看到的世界才真正有意义。

## 12 · 机器人也需要确认与澄清

系统甚至允许机器人**说话**。高层模型除了输出给低层的 skill command，还可以生成 verbal utterance，比如确认或者澄清；系统再用 text-to-speech 对用户说出来，然后把这部分语言从低层 command 中去掉。([arXiv][1]) 这里你可以看到一个很有趣的未来机器人接口：机器人的内部思考结果并不只是动作，它有时候应该先说“好的，我只清垃圾”，或者在不确定时提问。这样语言既是人→机器人的控制通道，也是机器人→人的协调通道。真正生活在家庭环境里的机器人，很可能不可能永远百分之百猜对人的意图，因此“会澄清”本身可能和“会抓东西”一样重要。

## 13 · 连接 π0、FAST 与推理模型

如果把 Hi Robot 和你刚读的 π0、FAST 连起来，三篇其实刚好覆盖三个层级。**π0 主要解决：怎样把视觉、语言和连续动作统一起来，让机器人拥有通用低层操作能力。FAST 主要解决：如果想用 autoregressive Transformer 做动作生成，怎样设计更好的 action tokens。Hi Robot 解决：即使底层已经会很多动作，怎样把复杂的人类目标、长程计划和实时反馈拆成底层能够可靠执行的简单技能。**所以 π0/FAST 更接近“身体和运动控制”，Hi Robot 更接近“意图和任务管理”。

如果再把它和你前面读的 DeepSeek-R1 放在一起看，会发现一个更大的趋势。R1 的核心是：难题不要指望一次生成就解决，让模型花更长时间做高层 reasoning；Hi Robot 的思想也类似：复杂机器人任务不要强迫一个 end-to-end policy 一次把语义、规划、动作全解决，而是给它一个更慢、更抽象的 reasoning loop。不同之处是，R1 的“思考结果”最后还是文字答案；Hi Robot 的高层思考结果则变成**下一条身体指令**。所以可以把 Hi Robot 看成一种 embodied reasoning：**推理不再只是为了回答问题，而是为了决定下一秒身体应该做什么。**

## 14 · 当前局限与统一模型的可能

不过这篇论文也有很明显的局限。首先，高层模型生成什么类型的指令，很大程度仍然受它训练时的 skill labels 限制；它不是凭空发明完全新的运动能力。其次，合成高层训练数据本身依赖 prompt engineering，作者也明确承认这点。第三，高层和低层是**分别训练**的，它们并没有真正联合学习彼此的能力：高层只是通过训练样本大概知道低层会什么，却不会根据低层实际执行成功率自动调整计划。([arXiv][1]) 换句话说，目前像一个经理和一个员工分别受训后被安排一起工作，但经理并没有真正通过长期合作学会“这个员工特别擅长什么、不擅长什么”。

作者因此提出了一个非常有意思的未来方向：**高层和低层未必最终需要是两个模型。**目前两个模型本来就几乎都由 PaliGemma VLM 出发，主要区别是低层多了 flow-matching action output。作者认为未来完全可能把两种能力合进一个统一模型，System 1 / System 2 的区别不再写死在模型架构里，而是在 inference 时决定：有些时候直接快速行动，有些时候先进入较慢的高层推理。([arXiv][1]) 这个想法特别值得记住，因为它和 reasoning LLM 的发展非常像：同一个模型面对简单题可以直接回答，面对困难题则投入更多 test-time compute。

## 15 · 用一分钟讲给朋友听

如果现在合上整篇论文，用费曼法一分钟讲给朋友听，我会这样说：**π0 已经可以让机器人根据“拿杯子”这种简单语言命令做出灵巧动作，但现实里人不会总是这么精确地说话，我们会说“帮我做个素食三明治”“只清理垃圾”“给我拿点甜的”，还会中途突然说“那个不是垃圾”。Hi Robot 因此在 π0 上面加了一个高层视觉语言模型：高层每隔大约一秒看一次当前场景和用户总要求，把复杂任务翻译成“拿生菜”“拿 KitKat”“把碗放回去”这种简单命令，再交给 π0 执行。为了训练这个高层，他们把真实机器人演示切成几秒钟的小技能，然后用一个强 VLM 根据‘当前画面 + 正确技能’反向生成大量可能的用户说法，从而得到丰富的合成互动数据。实验在清桌子、做三明治、买杂货，以及单臂、双臂和移动双臂三种机器人上进行，层级系统比直接使用 GPT-4o 做 planner 或让 π0 直接处理复杂指令更可靠，instruction accuracy 平均比 GPT-4o baseline 高 40% 以上。**([arXiv][2])

所以这一篇我建议最后只记住一句话：**π0 给了机器人“手”，Hi Robot 开始给这双手加一个会不断重新理解人类意图的“经理”。**📖 更技术一点就是：**High-level VLM reasons about intent，low-level VLA executes grounded skills，language becomes the interface between thinking and acting。**如果 π0 的关键问题是“怎样把理解变成动作”，那么 Hi Robot 的关键问题已经变成了：**怎样让机器人在行动过程中持续重新理解你。**这一步非常重要，因为真正的通用机器人绝不只是“你下一条命令，我做一个动作”，而应该能够在一个持续变化的物理世界里，边看、边做、边听你纠正，然后不断修改自己的计划。
