# DeepSeek-V3：让强大模型更高效

论文：DeepSeek-V3 Technical Report（2024）

## 01 · 大模型，能不能更省？

这一篇是《DeepSeek-V3 Technical Report》。如果沿着你前面读的 GPT-1 → GPT-2 → GPT-3 → GPT-4 继续往下看，这篇最值得抓住的核心其实不是“又一个更大的模型”，而是一个非常工程化、也非常现实的问题：**大模型已经证明“规模”很重要，但如果每次把规模扩大一倍，训练和推理成本也跟着爆炸，那这条路迟早会变得太贵。有没有办法让模型拥有几千亿参数的“知识容量”，但每处理一个 token 时，只动用其中一小部分？同时还能把训练、显存、通信、推理成本都压下来？** DeepSeek-V3 的答案就是：**不要让所有参数每次都工作，而是让模型像一家巨大医院一样，拥有很多专家，但每个病人只去找少数几个最合适的专家。**这就是 Mixture-of-Experts，也就是 MoE。DeepSeek-V3 一共有 6710 亿参数，但每处理一个 token 实际只激活大约 370 亿参数；作者在 14.8 万亿 token 上完成预训练，然后再经过监督微调和强化学习。

## 02 · MoE：只让少数专家工作

先用费曼法理解 MoE。假设你经营一家公司，公司里有 6710 亿个“神经元员工”。传统 dense 模型的做法像是：每来一个问题，全公司几乎所有相关部门都一起开会。模型越大，每次开会的人越多，计算成本自然越来越贵。MoE 换了一个思路：公司还是可以很大，但我安排一个“前台分诊员”，每收到一个 token，就判断这件事应该交给哪几个专家。例如代码 token 可能更经常被某些专家处理，数学表达式可能更偏向另外一些专家，中文和英文也可能形成不同程度的专业化。DeepSeek-V3 每个 MoE 层里有 1 个始终工作的 shared expert，再有 256 个 routed experts；一个 token 只会被路由到其中 8 个 routed experts。 所以它真正厉害的第一点可以压缩成一句话：**总参数决定“我能装多少东西”，激活参数决定“我每次花多少钱”。**DeepSeek-V3 想把这两个数字拆开。

## 03 · 怎样让专家合理分工

但 MoE 马上带来一个很麻烦的问题：如果路由器特别喜欢某几个专家怎么办？比如公司有 256 个专家，可前台发现“3 号、17 号、81 号好像什么都能干”，于是所有任务都送给他们，其他专家闲着。这会产生两个问题：第一，热门专家被挤爆，GPU 负载严重不均衡；第二，大量专家得不到训练，6710 亿参数中的很多容量等于白买了。所以传统 MoE 往往会额外加一个 **load-balancing auxiliary loss**，可以理解成给路由器一个行政指标：“你不能只用最喜欢的专家，必须尽量把工作分平均。”问题是，这个指标和模型真正想做的事情——“把下一个 token 预测准”——并不是完全一致的。如果为了均匀分工，硬逼一个本来最适合数学的 token 去找另一个不合适的专家，模型性能就可能受损。

DeepSeek-V3 在这里提出了一个很重要的改法：**auxiliary-loss-free load balancing，也就是尽量不用额外的负载均衡损失去扭曲原来的学习目标。**可以把它想成，不再给路由器说“每个专家必须接差不多一样多的单”，而是动态调整每个专家被选中的“门槛”或 bias：某个专家太忙了，就稍微提高它的门槛；某个专家太闲，就稍微降低门槛。这样最终工作量还是能趋向平衡，但不会给模型增加一个很强的“平均主义考试科目”。作者做消融实验，把其他条件尽量保持一致，发现这种 auxiliary-loss-free 策略在多数 benchmark 上比单纯依赖辅助损失的方案表现更好，而且专家之间会出现更明显的领域专业化。 费曼式地说就是：**以前是强迫每位医生每天接一样多的病人；DeepSeek-V3 更像调节挂号价格和排队规则，让病人自然分流，同时尽量保留“最适合的病人去最适合的医生”这件事。**

## 04 · MLA：压缩生成时的历史记录

第二个非常关键的东西叫 **MLA，Multi-head Latent Attention**。它解决的不是训练时“专家怎么选”，而是推理时另一个巨大成本：KV cache。Transformer 生成文字的时候，每生成一个新 token，都需要回头注意前面的 token。为了不重复计算，它会把过去 token 的 Key 和 Value 保存起来，这就是 KV cache。你可以把它想成模型一边聊天，一边给前文做大量笔记，后面随时翻阅。问题是，当模型很大、上下文很长、同时服务很多用户时，这本“笔记本”会大得惊人，显存会被 KV cache 吃掉很多。DeepSeek-V3 沿用 DeepSeek-V2 的 MLA：先把原本很大的 Key/Value 信息压缩成一个更小的 latent representation，需要时再恢复出注意力所需的信息。论文把其核心描述为对 attention keys 和 values 做 low-rank joint compression，以显著缩小推理时的 KV cache。 如果用生活里的比喻，普通 attention 像每参加一次会议就把完整录音永久保存；MLA 更像把录音压缩成高质量摘要和索引，需要时根据摘要恢复关键内容。**所以 MoE 主要省“每个 token 要算多少参数”，MLA 主要省“生成过程中要记多少历史”。**这两件事配起来，才真正让一个超大模型既大又能跑得动。

## 05 · MTP：让模型多预测一步

第三个特别有意思的改动是 **Multi-Token Prediction，MTP**。你前面一路读 GPT 系列，已经很熟悉那个最经典的训练游戏：“看前面，预测下一个 token。”比如输入“今天天气很”，目标只预测“好”；下一步才去预测后面的 token。DeepSeek-V3 问了一句：**为什么每次只逼学生想一步？如果让它不仅预测下一个 token，还同时学习再往后一两个 token，会不会迫使它对未来形成更丰富的计划？**于是 DeepSeek-V3 在训练时加入了额外的 multi-token prediction 模块，不只让当前表示为紧邻的下一个 token 服务，也让它承担更远一步的预测目标。论文的实现中，主模型之外增加 MTP 模块作为额外训练目标；推理时这些模块甚至可以直接丢掉，因此不会要求主模型永久背着额外训练结构运行。

这个 MTP 为什么可能提高能力？可以想象教学生写文章。如果我每次只问：“下一个字是什么？”学生可能只需要局部语法就能应付。但如果我要求他同时考虑“接下来一句大概往什么方向发展”，他就更需要建立更高层次的内部表示。对于代码尤其明显：写 `for (` 的时候，不只是下一个字符重要，模型最好已经对整个循环结构有一点预期。所以 MTP 可以理解成一种**让模型学着多看几步未来**的训练压力。论文的消融结果支持 MTP 对多种任务有帮助。更巧的是，这个训练技巧还能用于推理加速：第二个预测 token 的接受率在不同生成主题上达到大约 85%–90%，配合 speculative decoding，报告称可以达到大约 1.8 倍 tokens-per-second。 也就是说，同一个设计既可能让模型“学得更好”，又可能让模型“跑得更快”，这是很漂亮的一点。

## 06 · FP8：用更低精度稳定训练

接下来才到这篇报告里真正让工程圈非常关注的部分：**FP8 training。**传统大模型训练经常使用 BF16 或类似的 16-bit 数值格式。DeepSeek-V3 大量使用 8-bit floating point，也就是 FP8。为什么重要？你可以把浮点精度想成测量尺：16 位像一把刻度比较细的尺，8 位像一把刻度粗很多的尺。刻度粗意味着占的存储更少、计算更快、GPU 吞吐量更高，但风险也明显：数字误差可能积累，大模型训练几周以后稍微不稳定，就可能整个训练崩掉。DeepSeek-V3 做了大量针对量化、累加精度、通信、存储的设计，报告称他们在这样一个极大规模模型上成功验证了 FP8 mixed-precision training，而且整个正式训练过程中没有发生不可恢复的 loss spike，也没有进行 rollback。 这件事的意义不是“8 比 16 小一半”这么简单，而是：**如果低精度可以在超大规模上稳定工作，那么同样一批 GPU 就能做更多计算，或者同样模型可以花更少的钱。**

## 07 · DualPipe 与分布式工程

这篇论文其实有很大一部分并不是“AI 算法”，而是大型分布式系统工程。MoE 会产生一个特别讨厌的问题：一个 token 在 GPU A 上，但它需要的 expert 可能在 GPU B、C、D 上，于是 GPU 之间必须不停交换数据。模型规模一大，通信甚至可能比计算更慢。DeepSeek-V3 因此设计了 DualPipe，把前向、反向以及跨节点通信尽量重叠起来，让 GPU 在等网络数据的时候不要闲着；同时他们针对 NVLink 和 InfiniBand 做专门的 all-to-all 通信优化，并优化显存布局，使正式训练不依赖昂贵的 tensor parallelism。论文总结说，通过算法、训练框架和硬件的协同设计，他们把 MoE 的跨节点通信很大程度隐藏在计算过程里。 所以理解 DeepSeek-V3 非常重要的一点是：**它不是靠一个“神奇新公式”赢，而是几十个效率设计一起叠加。**这越来越像现代芯片设计：最后的性能来自算法、内存、通信、调度和硬件共同决定，而不是只看神经网络结构。

## 08 · 正式训练成本，不是全部研发成本

这就引出了这篇报告最出圈的数字：训练成本。论文报告完整训练共使用大约 **278.8 万 H800 GPU 小时**，其中正式预训练约 266.4 万 GPU 小时，context extension 约 11.9 万，post-training 约 5000；如果按每个 H800 每小时 2 美元计算，作者折算的正式训练成本约为 **557.6 万美元**。但这里一定要读得谨慎：论文自己也特别注明，这个数字只计算 DeepSeek-V3 的**正式训练 run**，不包括之前为了探索架构、算法、数据处理和消融实验所付出的研发计算成本。 所以“DeepSeek-V3 总共只花了 557 万美元”这种说法并不准确；更准确的说法是：**按照论文给出的 GPU 租赁假设，最终那次正式训练所对应的计算成本约 557.6 万美元，而整个研发项目的真实总成本没有在论文中给出。**这一点很值得记住，因为媒体报道很容易把“final training run cost”和“整个模型研发成本”混为一谈。

## 09 · 数据与长上下文

训练数据方面，DeepSeek-V3 使用了 **14.8 万亿 token**，英文和中文占主要部分。预训练完成以后，它又专门做了两阶段长上下文扩展：先从 4K 扩到 32K，再扩到 **128K**，并使用 Needle in a Haystack 测试验证在不同上下文长度和不同插入位置上能否找回隐藏信息。论文报告在最高 128K 的范围内表现仍然较稳健。 这里可以和你之前读 GPT-3 时做一个很直观的对照：GPT-3 当年的 context window 是 2048 token，DeepSeek-V3 已经在处理 128K。这意味着“模型的大脑”不只是参数多了，它一次能够放在工作记忆里的文字量也扩大了几十倍。长文档分析、代码库理解、多轮对话这些任务因此变得更现实。

## 10 · GRPO：更节省的强化学习

然后进入 post-training。DeepSeek-V3 和 GPT-4 一样，也不是“预训练完直接拿来聊天”。它先进行 SFT，也就是拿高质量的指令—回答数据继续训练，然后再做强化学习。这里使用的一个重要方法叫 **GRPO，Group Relative Policy Optimization**。传统 RLHF 里的 PPO 往往需要一个 critic / value model 去估计“这个回答比平均水平好多少”，而 critic 通常本身也很大，非常吃显存。GRPO 的想法可以粗略理解成：**针对同一道题一次生成一组答案，让这组答案互相比较，直接用组内相对成绩形成学习信号，因此不必另外养一个和 policy 差不多大的 critic。**论文描述为：对每个问题采样一组输出，用这些输出的组内分数估计 baseline，再优化策略模型。 这和整篇论文的主题高度一致：不仅模型架构讲效率，连强化学习阶段也尽量减少冗余计算。

## 11 · 从 R1 蒸馏推理能力

这里还有一个特别值得注意的桥梁：DeepSeek-V3 的后训练过程中，作者把 **DeepSeek-R1 系列模型的 reasoning 能力蒸馏给 V3**。 “蒸馏”用费曼法很好理解：想象一个很会数学、但解题特别啰嗦的老师 R1，他会花很长时间反思、检查、推导；另一个学生 V3 本来回答更直接。现在不是让 V3 从零重新发现所有推理技巧，而是把 R1 产生的高质量推理轨迹拿来教 V3，让 V3 学到其中的 verification 和 reflection 模式。作者强调，他们希望既获得 R1 带来的推理提升，又维持 V3 比较合适的回答长度和风格。 这其实指向了一条越来越重要的路线：**未来未必每个部署模型都要自己完成最昂贵的推理训练，一个“强老师”可以把能力转移给许多更便宜、更好用的学生模型。**

## 12 · 实验成绩与能力边界

实验结果上，作者报告 DeepSeek-V3 在知识、数学、代码和中文任务上都非常强。比如 MMLU 88.5，MMLU-Pro 75.9，GPQA 59.1；在论文当时比较的模型中，它被作者描述为最强的开源 base model 之一，并且 chat 版本在多个标准及开放式 benchmark 上达到和 GPT-4o、Claude 3.5 Sonnet 同一竞争区间。 但这里要像读 GPT-4 技术报告一样保持一个重要的阅读习惯：**benchmark 不是“智能总分”。**论文自己也展示了不同模型在不同任务上的强弱并不一致。例如软件工程类 SWE-bench Verified 上，DeepSeek-V3 仍落后于当时的 Claude 3.5 Sonnet；英文事实性 SimpleQA 上也落后于部分闭源模型，而中文事实知识方面则非常突出。 所以正确理解不是“DeepSeek-V3 全面超过所有模型”，而是“在相对低的正式训练成本下，它把开放权重模型推到了很多任务上和一线闭源模型接近的水平，尤其数学、代码和中文能力突出”。

## 13 · 把效率放到模型设计的中心

现在如果把它放回你前面读的历史里，会发现研究重点又发生了一次变化。**GPT-1 解决的是‘怎么从无标签文本获得通用能力’；GPT-2 问‘任务能不能自己从语言建模中出现’；GPT-3 问‘模型够大以后，能不能通过上下文而不是改参数来学新任务’；GPT-4 展示‘通用模型可以覆盖广泛专业能力和多模态输入，而且安全与对齐开始变得重要’；DeepSeek-V3 则在问另一个越来越现实的问题：‘既然大模型能力已经证明有效，我们怎样把同等级的能力做得便宜得多？’**所以 DeepSeek-V3 的历史意义，与其说是发现了一个全新的“智能原理”，不如说是把 **efficiency** 推到了基础模型设计的中心。

这里有一个特别值得记住的范式变化。早期 scaling 的直觉很简单：**想更聪明？加参数、加数据、加算力。**DeepSeek-V3 告诉你，现在真正的问题已经变成：**怎样让每一单位算力产生更多有效智能。**MoE 说“参数可以多，但别每次全用”；MLA 说“上下文可以长，但别把 KV cache 原样全部存下来”；FP8 说“计算可以多，但未必每个数字都需要 16 位精度”；DualPipe 说“GPU 可以分布在很多机器上，但别让它们空等通信”；MTP 说“训练时不要只预测一步，让同一个 token 提供更丰富的监督”；GRPO 说“强化学习可以做，但不一定非得额外训练一个巨大 critic”。把这些拼在一起，你会发现整篇论文其实反复在说同一句话：**不要只是堆资源，要重新设计资源怎样被使用。**

## 14 · 用一分钟讲给朋友听

如果现在把整篇论文合上，用费曼法要求你一分钟给朋友讲，我会这样说：**DeepSeek-V3 是一个总共有 6710 亿参数的大语言模型，但它用了 MoE，所以每处理一个 token 只激活大约 370 亿参数，像一家有很多专家的大医院，每个病人只找少数合适医生。为了让这些专家工作均衡，作者又设计了尽量不靠额外辅助损失的负载均衡方法；为了减少长上下文推理的显存，他们用 MLA 压缩 KV cache；为了让模型学得更好，他们让它训练时不仅猜下一个 token，还预测更远一点的 token；为了降低训练成本，他们把 FP8、GPU 通信、流水线并行等工程优化做到很极端。最后模型在 14.8 万亿 token 上预训练，并通过 SFT、GRPO 和来自 DeepSeek-R1 的推理蒸馏完成后训练，在许多数学、代码、知识和中文 benchmark 上进入当时顶级模型的竞争区间。**

所以如果你前面几篇论文各留下一句话，我会把这一篇记成：**GPT-1：让预训练产生可迁移能力；GPT-2：让任务从文本中自然出现；GPT-3：让上下文代替任务微调；GPT-4：让通用能力扩展到更多领域与模态；DeepSeek-V3：让强大模型不再等于每次都动用整个巨大模型。**📖 它最核心的公式不是某一个数学公式，而是一个工程思想：**More total intelligence capacity, less computation per token。**也就是“模型可以继续变大，但每一步真正付出的计算不必同比变大”。而如果你接下来继续读 DeepSeek-R1，就会看到这条故事线又往前走一步：V3 主要是在回答**怎样更高效地训练和运行一个强大的基础模型**，而 R1 开始更集中地回答另一个问题——**模型已经会很多东西以后，能不能通过强化学习，让它自己学会更长、更有效的推理过程。**
