# Knowledge Insulation：让机器人学习，同时留住旧知识

论文：Knowledge Insulating Vision-Language-Action Models: Train Fast, Run Fast, Generalize Better（2025）

## 01 · 新动作模块为何会干扰旧知识

这篇叫《Knowledge Insulating Vision-Language-Action Models: Train Fast, Run Fast, Generalize Better》。如果你刚刚读完 π0、FAST、π0.5，这篇其实是在把前三篇里一个一直存在、但之前没有被彻底说清楚的问题单独拎出来研究：**我们明明把一个已经很聪明的视觉语言模型 VLM 拿来做机器人，为什么一接上新的“动作模块”，它反而可能把原来从互联网学到的知识弄坏？**换句话说，VLA 的理想故事本来是：“VLM 已经认识杯子、抽屉、衣服，也听得懂语言，我们只需要再教它怎么动手。”但作者发现实际训练时并没有这么简单。像 π0 那样给预训练 VLM 接一个随机初始化的 flow-matching action expert，然后让动作损失一路反向传播回 VLM，会明显拖慢训练，还可能破坏原来的语言理解和语义知识。于是这篇论文提出一个很形象的概念：**Knowledge Insulation，知识绝缘。**你可以让动作专家从 VLM 获取信息，但不要允许这个刚出生、还在乱学的动作专家用自己的梯度把已经训练成熟的 VLM 大脑搅乱。

先用费曼法想象一个场景。你请来一个非常博学的经理，他看过几乎所有商品图片，也听得懂“把勺子扔进垃圾箱”“把红色杯子放进抽屉”这种指令。现在你又招了一个完全不会干活的新员工，负责真正用手搬东西。正常的想法是让两个人一起培训：员工搬错了，整个团队一起接受反馈并修改。但问题是，新员工刚开始几乎什么都不会，他产生的错误信号非常混乱。如果这些信号一路传回经理，经理原本很稳定的“什么是勺子、用户到底说了什么”也会跟着被不断改写。结果训练了一段时间以后，员工动作也许稍微会了一点，但经理反而开始不听人话了。这就是作者对 π0 式直接 joint training 的核心担忧：**随机初始化的新模块不仅自己要学习，还会通过梯度干扰预训练模型中已经很宝贵的表示。**

## 02 · 完全冻结 VLM 也不够

你可能马上想到一个最简单的办法：那我把 VLM 完全冻住不就好了？经理不许改变，只训练新员工。作者真的试了，结果也不行。原因非常关键：**互联网 VLM 的知识虽然丰富，却不是为机器人控制形成的表示。**它看到一个抽屉可能知道“这是抽屉”，但并没有被训练过如何把视觉表示组织成“手离把手有多远、接下来应该往哪个方向运动”这种控制信息。如果 backbone 一点都不能改，action expert 就只能从一套并不适合机器人控制的固定特征里硬挤动作信息，实验里甚至会出现接近 0 的表现。所以正确答案既不是“全部一起乱改”，也不是“VLM 一点不许改”，而是：**VLM 应该继续学习机器人，但要通过更干净、更稳定的学习信号来学习。**

## 03 · 两种动作表示与梯度隔离

这就引出了整篇论文最漂亮的设计：**同时训练两种动作表示。**同一条真实机器人轨迹，一份用你前面读过的 FAST 编码成离散 action tokens，让 VLM backbone 像做语言模型一样通过 next-token prediction 学“下一段动作是什么”；另一份则保留成连续动作，交给小型 action expert 用 flow matching 学。关键是，flow-matching action expert 的梯度在进入预训练 backbone 前被 **stop-gradient** 截断。也就是说，VLM 会因为 FAST 动作 token 而真正适应机器人任务，但不会直接受到随机初始化 action expert 的梯度冲击；与此同时，action expert 仍然可以通过 attention 读取 backbone 已经学出来的视觉、语言和机器人表示。

所以如果把 Knowledge Insulation 压缩成一句极容易记住的话，就是：**信息可以从 VLM 流向 action expert，但坏梯度不要反过来污染 VLM。**这和电路里的“绝缘”很像：两个部分仍然可以协作，不等于完全隔离，而是控制什么东西能够跨边界传播。FAST action tokens 在这里的角色也发生了变化。FAST 那篇论文主要把它当成真正的机器人输出方式；但在这篇论文里，FAST 更像一种 **representation-learning objective**。训练时让 backbone 预测 FAST token，是为了逼它学出“跟动作有关”的表示；真正部署时却根本不用慢吞吞地一个 token 一个 token 生成 FAST，而直接让更小的 action expert 输出连续动作。论文自己把这个组合概括成：训练得到 FAST 的收敛速度，同时部署得到 flow matching 的推理速度。

## 04 · FAST 负责教，Flow 负责做

这其实把你之前看到的 π0 和 FAST 的矛盾解决得更彻底了。π0 的优点是连续动作生成快而精确，可以达到高频控制，但作者发现它只靠 flow loss 训练时收敛慢，而且容易损害语言跟随；π0-FAST 的优点是标准 next-token prediction 特别好训练，也更容易保持 VLM 语义知识，但运行时 autoregressive decoding 太慢——论文引用的例子是生成一秒动作大约要 750ms，而 π0 的小 action expert 可以做到约 10Hz 控制。Knowledge Insulation 的想法不是选边站，而是说：**FAST 负责教，Flow 负责做。**训练阶段两条路线同时存在，真正运行机器人时只走连续动作那条快速通道。

## 05 · 共同训练，保留视觉语言知识

而且作者还加了第二层“知识保护”：**继续混合普通 VLM 数据一起训练。**也就是说，机器人训练期间不要让模型天天只看“图像 + 关节 + 动作”，还继续给它做 VQA、图片描述、bounding-box prediction、机器人高层规划等非动作任务。为什么？因为这相当于不断提醒它：“你现在虽然在学机械臂，但别忘了你以前为什么聪明。”如果一个学了医学的学生后来天天只做肌肉记忆训练，几年后专业知识当然可能退化；co-training 就像让他一边练操作、一边继续复习知识。实验里这种 VLM co-training 对**从网页知识向机器人动作迁移**尤其重要：面对训练机器人数据里从未出现过的新物体，混入 VLM 数据的模型更容易正确理解语言并操作这些对象。

## 06 · 从 π0.5 的两阶段到统一训练

这也是这篇论文和 π0.5 最直接的关系。π0.5 已经使用一种“两阶段”思路：第一阶段主要靠 FAST token 和各种视觉语言数据做大规模预训练，第二阶段才把随机初始化的连续 action expert 接进来做 post-training。这篇 KI 论文其实是在问：**为什么 π0.5 这种做法有效？能不能把背后的原则说清楚，然后做成一次性训练？**作者给出的答案就是 knowledge insulation。他们不必先完成离散训练、再单独进入连续训练，而是在同一个训练阶段同时学习 FAST 和 flow，只是控制梯度路径。论文因此把 π0.5 背后比较经验性的做法，进一步提炼成一个更一般的 VLA 训练原则。

## 07 · 收敛速度与语言跟随

实验特别能说明这个问题。作者测试了收拾桌面、把物体放进抽屉、把盘子放进水槽、双臂折 T-shirt、移动双臂操作，同时还测 DROID 和 LIBERO。最值得看的不是某个 benchmark 数字，而是几条非常稳定的规律。第一，直接用 flow matching 的 π0 学得明显更慢；在 table bussing 的 generalist setting 里，论文报告 π0 大约需要 **7.5 倍训练 steps** 才达到类似表现，而 Knowledge Insulation 的收敛速度接近 π0-FAST。第二，π0-FAST 虽然学得快、语言跟随也不错，但现实运行慢，同一个任务整体完成时间可能约为他们方法的两倍。第三，既不给 stop-gradient、又不给 VLM co-training 的普通 joint training 很容易在语言跟随上出问题。也就是说，作者真正实现了标题那三个词：**train fast、run fast、generalize better。**

“语言跟随”在这篇论文里尤其重要。机器人训练数据本身往往存在很强的视觉偏差：如果训练录像里桌上经常是垃圾，那么机器人可能看到某种画面以后直接开始收垃圾，根本懒得听用户到底说“拿勺子”还是“拿纸杯”。这有点像学生发现考试总是选 C，于是成绩不错，但实际上不读题。作者认为如果 VLA 在微调过程中把原 VLM 的语言知识损坏了，它就更容易退化成这种“看图猜动作”的策略。实验也显示，阻断 action expert → backbone 的梯度以后，模型更愿意真正按照语言选择正确物体；加入 VLM co-training 后效果还会进一步改善。

## 08 · 预训练知识也会被破坏

这里还有一个很容易被忽略、但我觉得特别重要的结论：**预训练知识不是一个“模型里面有或没有”的二元属性，它可以在后续训练中被破坏。**以前我们说“拿一个预训练 VLM 做机器人”，容易产生一种错觉，好像互联网训练得到的所有语义知识天然就会完整地转移过去。但这篇论文提醒我们：architecture 和 gradient path 本身决定了这些知识能保留多少。也就是说，foundation model transfer 不只是“初始化权重，然后 fine-tune”这么简单，而是要研究**新任务产生的梯度怎样改变旧知识**。这和语言模型领域里的 catastrophic forgetting，本质上是同一类问题，只不过这里因为新接入的 action expert 是随机初始化、输出模态又完全不同，冲突变得更加明显。

## 09 · 离散监督信号也需要好表示

另外，作者也验证了“简单地把动作离散一下”还不够。他们把 FAST 换成普通 naïve action tokenization，其他东西保持相同，结果虽然仍然比纯连续 flow 训练好，但不如 FAST；把稠密动作序列做时间下采样会改善一些。 这和 FAST 那篇论文的核心发现完全对应：高频机器人动作里相邻时间点太相似，普通 tokenization 的监督信息密度很低，而 FAST 通过频域压缩后，每个 token 更有意义。所以这里其实再次证明：**Knowledge Insulation 并不是随便找一个离散动作辅助 loss 就行，给 backbone 的学习信号本身也要足够好。**

## 10 · 实验结果与训练代价

最终结果上，他们的方法在真实机器人测试里总体表现最强，在 DROID 上报告约 **0.55±0.09**，π0 约 0.49，π0-FAST 约 0.45；在 LIBERO 上，他们从 generalist KI 模型继续 fine-tune 后，在 LIBERO-90 达到 96.0%，并在 LIBERO-Spatial 上达到当时很强的结果。 但我认为最值得记的仍然不是排行榜，而是实验把几个 trade-off 拆开了：**离散动作适合学表示，连续动作适合实时控制；VLM 数据适合保语义，机器人数据适合学身体；stop-gradient 适合防止新模块破坏旧知识。**这三件事组合起来，才形成完整的 recipe。

它也不是完全没有代价。因为训练时同时做离散和连续动作预测，论文估计训练单步计算量增加大约 **20%**；但由于收敛速度明显提高，总 wall-clock training 仍然比 π0 这种纯 flow VLA 快。语言跟随也没有被彻底解决，作者承认由于机器人数据本身强烈相关，模型有时仍然会无视指令。 所以 Knowledge Insulation 不是“VLA 最终架构”，它更像发现了一个训练时必须认真对待的新问题：**越强的预训练模型，越不能粗暴地把一个随机新模块焊上去，然后假设联合反向传播会自动保留所有好东西。**

## 11 · 从能力设计到知识迁移

如果现在把 π0 → FAST → Hi Robot → π0.5 → KI 连成一条线，你会发现每篇都在补一个不同的缺口。**π0：怎样高频、连续地控制机器人；FAST：怎样把动作压成适合 Transformer 学习的 token；Hi Robot：怎样把复杂人类意图拆成高层任务和低层动作；π0.5：怎样把网页、跨机器人、高层规划和真实家务共同训练，获得陌生环境泛化；Knowledge Insulation：既然我们越来越依赖强大的预训练 VLM，那训练机器人时怎样避免把这些来之不易的知识自己破坏掉。**所以这篇其实是在从“模型能力设计”进一步走向“知识迁移机制设计”。

## 12 · 用一分钟讲给朋友听

如果现在合上论文，用一分钟讲给朋友听，我会这样说：**机器人 VLA 通常是在一个已经很聪明的视觉语言模型旁边接上一个新的连续动作模块。但这个动作模块刚开始是随机的，它产生的训练梯度会反过来破坏 VLM 原本学好的视觉和语言知识，所以 π0 之类的模型可能学得慢、也更容易不听语言。作者提出 Knowledge Insulation：同一条机器人动作训练两份，一份用 FAST 变成离散 token，让 VLM 本体用标准 next-token prediction 学会机器人相关表示；另一份交给小 action expert 用 flow matching 学连续动作，但阻止 action expert 的梯度回到 VLM。同时继续混入 VQA、图片描述等普通 VLM 数据，防止语义知识遗忘。真正运行机器人时不用 FAST，只让小 action expert 快速输出连续动作。这样既保留了 FAST 学得快的优势，也保留 π0 连续控制运行快的优势，而且语言跟随和新物体泛化更好。**

所以这篇我建议最后只记一句话：**Learn robotics through the backbone, but don’t let a newborn action head rewrite the backbone.** 📖 中文就是：**让 VLM 学会机器人，但不要让一个刚初始化的动作专家反过来把 VLM 已经学好的世界知识洗掉。**如果 π0.5 的核心问题是“怎样把更多知识带进机器人”，那么 KI 紧接着问的是一个更深的问题：**知识带进来以后，训练过程中怎样把它留住。**
