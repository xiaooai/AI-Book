# π0.5：在陌生世界里迁移多种知识

论文：π0.5: a Vision-Language-Action Model with Open-World Generalization（2025）

## 01 · 第一次进入陌生家庭

这篇是 Physical Intelligence 的《π0.5: a Vision-Language-Action Model with Open-World Generalization》。如果把你前面读过的 π0、FAST、Hi Robot 接起来看，π0.5 其实是在回答一个更接近“真正家用机器人”的问题：**机器人在实验室里会做动作还不够，它能不能进入一个从来没见过的家，面对从来没见过的厨房布局、卧室、物体和摆放方式，只听一句“把厨房收拾一下”，就自己拆任务、找东西、移动、抓取、整理，并连续工作十几分钟？**π0 已经证明一个 VLA 可以把视觉、语言和连续动作统一起来；FAST 证明动作也可以被高效 token 化；Hi Robot 又证明长任务最好加入高层语义规划。π0.5 把这些线索重新收拢到一个模型里，把研究重点从“会不会操作”推到了 **open-world generalization，也就是离开训练环境以后还能不能干活。**论文展示的 π0.5 可以在训练时完全没见过的新住宅里清理厨房和卧室，执行 10–15 分钟的多阶段任务。

## 02 · 泛化需要不同来源的知识

先用费曼法理解作者为什么觉得之前的方法还不够。假设你训练机器人时，让它在同一个厨房里练了一千次“把盘子放进水槽”。最后它成功率可能非常高，但这并不代表它真的学会了“收拾厨房”。换一套房子以后，水槽换了方向，盘子长得不一样，抽屉位置改变，旁边还多了一个沥水架，机器人可能马上崩掉。现实世界的问题是组合数量几乎无限：你不可能把全世界所有厨房、所有盘子、所有毛巾、所有抽屉都提前让机器人练一遍。论文因此提出一个很像人类学习的观点：**真正的泛化不能只靠目标机器人自己的第一手经验，而必须把不同来源的知识拼起来。**人第一次去朋友家收拾厨房，也不是因为以前见过一模一样的厨房；他会调用过去收拾别的房间的经验、知道“盘子”“抽屉”“沥水架”这些概念、理解别人说的指令，再现场组合出解决方案。π0.5 想让机器人也这么学。

## 03 · 异构数据共同训练

所以 π0.5 最重要的关键词不是“更多机器人数据”，而是 **heterogeneous co-training，异构数据共同训练**。它当然有目标移动机器人的真实家庭数据，大约 400 小时，但这只是一部分；它还学习其他固定机械臂的数据、其他机器人 embodiment 的数据、实验室里的各种操作任务、高层 subtask prediction、人工监督者说出的语言指令，以及网页上的图像描述、视觉问答、物体定位等多模态任务。更惊人的一个数字是：在第一阶段训练中，**97.6% 的训练样本并不是“这台移动机器人在家里做家务”的数据**，而来自这些其他来源。 这说明论文真正想证明的是：**机器人不应该只从自己的身体经验学习；别的机器人的动作经验、互联网的视觉语义知识、语言监督，都可以转移成它在新环境里的能力。**

这里可以想象一个刚入职的家政机器人。它直接在真实移动机器人上只工作了 400 小时，这远远不够覆盖全世界的住宅。但它还“旁听”过其他机械臂成千上万次抓取和操作，看过互联网里大量不同物体和场景，也练过“看到这个画面以后，下一步应该做什么”这种高层语义题。于是当它进入一间陌生卧室，看到地上的衣服时，它不需要以前在**这间卧室**捡过这件衣服；只要视觉知识告诉它“这是衣服”，其他机器人经验告诉它“柔软物体通常怎么抓”，高层知识告诉它“clean the bedroom”时衣服通常应该进 laundry basket，再把这些能力组合起来，就有可能完成任务。π0.5 想验证的就是这种 **knowledge transfer across sources**。

## 04 · 同一个模型，先规划再行动

它的第二个关键改变，是把 Hi Robot 那种“高层想下一步、低层负责动手”的思想直接塞进**同一个模型**。运行时，如果用户说“clean the bedroom”，π0.5 不会直接从这五个词一路预测几十维关节动作。它先生成一个高层语义 subtask，例如“pick up the pillow”；然后再以这个 subtask 为条件，生成真正的低层动作。下一阶段可能又判断“rearrange the pillow”或者“pick up clothing”。作者明确把这种结构类比成 chain-of-thought 或 test-time compute：模型先产生一个中间的语义步骤，再行动。和 Hi Robot 很大的不同是，Hi Robot 更像一个高层 VLM 加一个独立 π0 controller，而 π0.5 让**同一套模型参数同时承担 high-level 和 low-level inference**。

这个区别很值得理解。想象 Hi Robot 像“经理 + 工人”两个不同的人：经理说“拿盘子”，工人负责执行；π0.5 则更像同一个人先在脑中想一句“我现在应该先拿盘子”，然后身体照着这个内部目标行动。这样，高层语义和低层运动可以共享大量视觉表示，而且同一个训练体系可以同时吸收网页知识和机器人动作知识。论文里的结构图很直观：输入包括图片和高层 prompt，模型先自回归生成低层语言 subtask，然后 action expert 根据这个 subtask 和当前观察生成连续动作。 这已经很接近一种简化版的“机器人思维链”：**先说清楚下一步要干什么，再让身体执行。**

## 05 · FAST 与 flow matching 的结合

然后出现了一个特别漂亮的设计：π0.5 把你上一章读过的 **FAST 和 π0 的 flow matching 两条路线都用了**。FAST 论文告诉我们，把连续动作先压成离散 action tokens，特别适合大规模 autoregressive 预训练，训练效率高、可以和语言/视觉任务统一；但 FAST 也有缺点——推理时一个 token 一个 token 地生成动作比较慢。原版 π0 的 flow matching 恰好相反：连续 action chunk 生成特别适合实时控制，但如果在所有预训练数据上都一直用 action expert 做 flow matching，大规模联合训练没有离散 token 那么方便。π0.5 因此问：**为什么一定要二选一？训练时用 FAST 获得统一、稳定、高效的 token 学习，部署时再用 flow matching 快速产生连续动作。**

具体来说，π0.5 第一阶段把语言、object location、以及机器人动作都变成可以做 next-token prediction 的序列，其中动作使用 FAST tokenizer。这样它就很像一个真正的多模态 GPT：有时候预测文字，有时候预测框，有时候预测 robot action tokens，所有异构数据可以进入统一 Transformer 训练。到了第二阶段 post-training，才加入 π0 那个较小的 action expert，训练 flow-matching continuous actions。实际运行时，模型先 autoregressive 地生成高层 subtask 文本，然后 action expert 用大约 10 个去噪步骤生成连续 action chunk。 所以 π0.5 的配方可以非常简洁地记成：**Pretrain discretely，act continuously。预训练离散化，执行连续化。**

这件事其实把 π0 和 FAST 之间原本看起来像“路线竞争”的关系变成了合作。上一章我们还在问：“未来机器人动作到底应该 flow matching 还是 autoregressive tokens？”π0.5 给出了第三种答案：**训练表示和部署表示不一定必须一样。**就像一个人学习驾驶时可以先通过书本、规则和模拟器形成离散知识，但实际开车时动作必须连续。FAST 负责让机器人数据方便进入大规模统一学习框架，flow matching 负责让最终控制保持连续、细腻和实时。这种“训练接口”和“执行接口”分开优化的思想，是 π0.5 很值得记住的一点。

## 06 · 移动双臂与连续控制

机器人本身也不是简单的桌面机械臂。论文使用两种移动双臂平台，每台都有两只 6-DoF 手臂、两个夹爪、可以全向移动的底盘、升降 torso，以及前后和两个手腕一共四个摄像头，整个 state/action space 大约 18–19 维。底层控制直接以 **50 Hz** 输出手臂、夹爪、升降和底盘目标，中间并没有额外复杂的轨迹规划器或者碰撞规划器，只有简单 PD control 去跟踪目标。 这点很重要，因为“收拾卧室”并不是 planner 先算好一整条路径，然后机器人只负责执行；论文想展示的是大量 perception、navigation 和 manipulation 行为真的来自 learned policy 本身。

## 07 · 在未见过的住宅中测试

然后来看作者怎么证明“open-world generalization”不是一句营销词。他们故意把所有主要实验都放到训练期间**没见过的环境**里，并且最后直接进三套真实住宅测试。在新厨房和卧室中，他们让机器人完成“把东西放进抽屉”“把衣服放进洗衣篮”“把盘子放进水槽”等多阶段任务，每个任务可能持续 2–5 分钟；更复杂的演示则能连续做 10–15 分钟的整屋整理。测试住宅在训练数据里完全不存在，布局、背景、物体实例也都是新的。 这比传统 VLA 测一个几十秒的“拿起陌生杯子”难很多，因为长任务里任何一个步骤出错，后面的状态都会偏离训练分布。

## 08 · 环境多样性也需要扩展

一个很有说服力的实验是：**训练时见过多少个不同家庭环境，会怎样影响泛化？**作者分别使用来自 3、12、22、53、82、104 个地点的数据训练，然后都去没见过的 test homes 里做家务。结果随着训练地点越来越多，完整长任务表现和语言跟随能力都稳步提高。更有意思的是，使用 104 个训练地点的模型，在完全没见过测试家的情况下，最终表现已经接近一个“作弊版”baseline——那个 baseline 是直接看过测试住宅训练数据的。 用费曼法说，就是学生不一定非得提前见过考试原题；如果他去过足够多不同类型的厨房，逐渐学到“厨房变化的规律”，第一次进入第 105 个厨房，也能接近一个提前在里面练过的人。

这其实非常像大语言模型的 scaling，只不过这里 scaling 的横轴不只是 token 数，而是 **environment diversity**。网页语言模型为什么泛化好？因为它看过极其多样的文章、风格和主题。机器人如果只在三个实验室桌面上收集十万小时，很可能只是把三张桌子背得特别熟；论文的实验暗示，对机器人来说，“见过多少种不同世界”可能和“总共见过多少小时”同样重要。作者控制了训练样本数量后依然观察到环境数量增加带来的改善，这说明收益不只是“数据更多”，还有真正的**场景多样性**贡献。 这可能是 π0.5 最值得长期记住的结论之一：**robot scaling law 可能不仅是 hours scaling，还包括 world diversity scaling。**

## 09 · 其他机器人的经验能否迁移

接着看消融实验，就会发现这些异构数据不是随便堆在一起。去掉其他环境里的静态机器人数据，性能明显下降；去掉跨 embodiment 的实验室机器人数据也明显下降；两个都去掉，下降更严重。这意味着一台移动机器人真的可以从“身体不一样”的固定机械臂身上学东西。 为什么？因为“拿起盘子”“折衣服”“把物体放进容器”这些技能包含一部分和具体底盘无关的视觉—动作结构。就像一个人会开轿车以后学 SUV 并不从零开始，身体结构虽然不完全一样，但大量知识可以迁移。

## 10 · 网页知识扩展物体认知

网页数据的作用则更微妙。单纯在熟悉类别的家务任务上，去掉 web data 有时差别不显著；但一旦测试**训练中从没出现过的物体类别**，没有网页数据的模型明显更差。作者推测原因很自然：robot dataset 无论再大，也不可能让机器人真正摸过世界上所有东西，但互联网 VLM 已经看过巨量物体。 比如机器人从来没有操作过某种特殊厨具，但 web pretraining 也许至少告诉它“这是什么、大概在哪里、长什么样”。于是互联网知识不能直接教机械臂“手腕转几度”，却能解决“我要操作的到底是什么东西”。这正好体现 heterogeneous co-training 的分工：**robot data 教 physical affordance，web data 教 semantic coverage。**

## 11 · 语言监督连接目标与动作

语言监督也出现了类似效果。post-training 中只有一部分高层样本来自人类监督者现场对机器人说话，这种 verbal instruction 数据占高层移动机器人样本大约 **11%**，比例并不大；但拿掉以后，高层性能却明显恶化。 这很像一个学生光看动作录像，会知道“下一步经常拿盘子”，但如果有人一边做一边说“现在把盘子放进水槽，因为我们在清厨房”，他会更容易把语言目标、视觉状态和动作结构对齐。少量语言数据在这里起到的是一种“胶水”作用，把不同抽象层连接起来。

## 12 · 高层推理与身体约束

高层推理的实验也很有意思。完整 π0.5 是最强的；如果运行时不显式生成 subtask，但训练期间仍然给模型看过大量高层 subtask examples，性能居然还是第二好。这说明一部分“规划知识”已经被 co-training **内化进模型表示**，即使推理时不把那句话明确说出来，也能得到收益。相反，如果训练时连高层数据都彻底拿掉，性能明显更差。 这和语言模型里的 chain-of-thought 有一点很有趣的呼应：**显式中间推理有帮助，但学习过推理任务本身也可能改变模型内部表示。**

更让人意外的是，他们还拿 GPT-4 当外部高层 planner，让 GPT-4 根据环境和任务选下一步，然后让 π0.5 的低层去执行。这个 zero-shot GPT-4 高层 baseline 反而表现最差。 这和 Hi Robot 的结论高度一致：**一个很聪明的通用 VLM/LLM，不代表它天然会给机器人规划。**它知道世界常识，却不一定知道“这台机器此刻看到了什么、身体够得到什么、哪些 subtask 是它真正训练过并能稳定完成的”。π0.5 的高层虽然模型不一定更“博学”，却被机器人经验牢牢 ground 过，所以更懂“这个身体下一步应该干什么”。具身智能里一个反复出现的规律就是：**reasoning 要有身体约束。**

## 13 · 不只是把 π0 训练更久

和原版 π0 正面对比时，π0.5 也明显更好。为了公平，作者甚至做了一个加强版 π0-FAST+Flow：同样有 FAST + flow 的混合训练，但不给它 web data 和 high-level data。即使这样，完整 π0.5 在 mock home 测试里仍然显著领先 π0 和 π0-FAST+Flow；把原版 π0 训练到更多 steps，也没有追上。 这说明真正带来 open-world 泛化的并不是“把 π0 训练更久”，而是**训练任务本身变得更丰富了**。这是这篇论文非常核心的观点：当机器人想走出实验室时，单纯扩大 imitation-learning action dataset 可能不够，你需要扩大它接触的**知识类型**。

## 14 · 从操作能力到开放世界泛化

如果把 π0、FAST、Hi Robot、π0.5 连起来，就能看到 Physical Intelligence 这条路线非常清楚的演化。**π0 首先解决“一个通用 VLA 怎样产生高质量连续动作”；FAST 解决“动作怎样 token 化，才能高效进入大规模 Transformer 训练”；Hi Robot 解决“复杂人类意图怎样通过高层 planner 分解成低层技能”；π0.5 则把这些思想统一起来，进一步问“怎样让同一个模型利用其他机器人、互联网、高层语义和语言监督，在完全陌生的物理环境里完成长任务”。**于是研究目标已经从 manipulation generalization 逐渐变成真正的 **open-world physical intelligence**。

而如果把它再和你之前读的 GPT 系列放在一起，联系会更深。GPT-1 到 GPT-4 的成功很大程度来自一个事实：模型的能力不是只从“目标任务数据”里获得的。一个 GPT 模型会写代码，不是因为它只训练代码；会回答医学问题，也不是每次重新训练一个医学模型，而是各种异构知识在同一个基础模型里发生迁移。π0.5 在机器人领域尝试的其实就是同一种范式：**做家务的数据不一定全部来自“做家务”。**网页里的视觉知识、别的机器人抓东西的经验、人类的一句语言指导、高层 subtask prediction，都可能最后变成“第一次进入陌生厨房也知道该怎么办”的能力。

## 15 · 用一分钟讲给朋友听

如果现在合上论文，用费曼法一分钟讲给朋友听，我会这样说：**π0 已经让机器人学会根据视觉和语言做灵巧动作，但它主要还是在和训练环境比较接近的地方工作。π0.5 想解决的是：机器人能不能第一次进入一个陌生家庭，也把厨房和卧室收拾好。作者没有只收更多目标机器人数据，而是把很多不同知识源一起训练：约 400 小时移动机器人真实家务、其他机械臂的数据、跨机器人任务、高层“下一步该做什么”的语言标签、人类现场指令，以及网页上的视觉语言数据。第一阶段把动作通过 FAST 变成 token，和语言、图片任务一起做 next-token prediction；第二阶段再加入 flow-matching action expert，让部署时可以快速生成连续动作。运行时同一个模型先想出“pick up the plate”这样的高层 subtask，再生成低层动作。最后，它能在训练中完全没见过的新住宅里连续做多阶段家务，甚至完成 10–15 分钟的厨房或卧室整理；而消融实验说明，其他机器人的经验、网页知识和高层语言训练都对这种泛化有实质贡献。**

所以这篇论文我建议你最后只记一句话：**π0 taught the robot how to act；π0.5 teaches it how to reuse many kinds of knowledge in a world it has never seen。**📖 中文就是：**π0 主要解决“手怎么动”，π0.5 开始解决“到了陌生世界，怎样把过去在别的身体、别的场景、网页和语言里学到的东西重新组合起来”。**而它最值得关注的变化，不是模型又大了一点，而是机器人训练范式开始真正向 foundation model 靠拢：**未来机器人能力的瓶颈，可能不只是缺少更多动作数据，而是缺少一种能把所有不同形式的经验统一吸收、统一迁移的训练方法。**
