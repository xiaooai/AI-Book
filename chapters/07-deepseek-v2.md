# DeepSeek-V2：稀疏计算与压缩记忆

论文：DeepSeek-V2: A Strong, Economical, and Efficient Mixture-of-Experts Language Model（2024）

## 01 · 强、便宜、推理快

这一篇是 2024 年的《DeepSeek-V2: A Strong, Economical, and Efficient Mixture-of-Experts Language Model》。如果你刚刚读完 DeepSeek-V3，再倒回来读 V2，会很有意思，因为你会发现 V3 里很多最重要的东西——MLA、DeepSeekMoE、GRPO、128K 上下文、强调训练和推理效率——其实都已经在 V2 里搭好了骨架。V3 更像把这套思想继续做大、做稳、做便宜，而 V2 才是那个真正明确提出“我们不仅要把模型做强，还要把每个 token 的成本压下来”的关键转折点。作者开门见山地说，大语言模型参数越来越多通常会带来更强能力，但训练成本和推理吞吐会恶化，所以 DeepSeek-V2 的目标是同时做到三件事：强、便宜、推理快。它一共有 2360 亿参数，但每个 token 只激活约 210 亿参数，同时支持 128K 上下文。([arXiv][1])

## 02 · MoE：拆开容量与计算成本

先用费曼法理解它最核心的问题。假设你开了一所拥有 2360 亿“知识单元”的超级学校，如果每来一道题，2360 亿个单元全部参与计算，那么模型当然可能很强，但每回答一个字都非常贵。DeepSeek-V2 的做法是：学校可以很大，但每道题只叫少数真正相关的老师来回答。这个结构就是 Mixture-of-Experts，也就是 MoE。传统 dense 模型像“所有老师每节课都必须到场”，MoE 则像“先分诊，再让少数专家工作”。所以 DeepSeek-V2 虽然总参数达到 236B，但每个 token 实际只动用大约 21B。([arXiv][1]) 这件事最重要的思想可以记成一句话：**模型能装多少知识，由总参数决定；每次回答要花多少钱，更接近由激活参数决定。**也就是说，DeepSeek-V2 想把“容量”和“计算成本”拆开。

## 03 · 细分专家与共享专家

但是普通 MoE 并不自动意味着好用，因为“专家”怎么分也很关键。想象医院里有很多科室，如果科室太大，一个专家同时负责数学、代码、中文、物理，专业化可能不够；如果完全让所有专家自己竞争，又可能很多专家重复学同样的东西。DeepSeek-V2 使用的 DeepSeekMoE 做了两个特别重要的设计。第一个叫 **fine-grained expert segmentation**，也就是把传统的大专家切成更多、更细的小专家，让路由可以更精确地组合它们；第二个叫 **shared expert isolation**，即专门留下部分所有 token 都会经过的共享专家，把那些很多领域都会反复用到的通用知识放进去，从而让其他 routed experts 更专注于各自特殊领域。论文认为，在总专家参数和激活参数相同的情况下，这种设计能明显优于传统 MoE。([arXiv][2]) 用生活里的比喻就是：医院不再只有几个“全科大科室”，而是拆成很多细分专科，同时保留一个公共急诊科处理每个人都需要的基础问题。这样既减少重复，又提高专业化程度。

## 04 · 路由也要考虑通信成本

这里马上又出现一个工程问题：这些专家可能分布在不同 GPU 上。如果一个 token 同时需要访问很多机器上的专家，GPU 之间要疯狂传数据，那么省下来的计算又会被通信成本吃掉。所以 DeepSeek-V2 又加入了 **device-limited routing**，限制每个 token 最多跨多少设备去找专家。([arXiv][2]) 费曼式地讲，就是虽然医院有很多分院，但不能让一个病人为了看 8 个专家横跨 8 个城市，否则专家虽然厉害，交通已经把效率毁掉了。所以路由不仅要问“哪个专家最适合”，还要问“怎样在不大量跨机器通信的情况下找到一组足够好的专家”。这说明到了这种规模，大模型架构已经不能只从“神经网络数学”考虑，还必须把 GPU 怎么连、数据怎么传一起设计。

## 05 · MLA：压缩历史记忆

不过 DeepSeek-V2 真正最有代表性的创新，我认为是 **MLA：Multi-head Latent Attention**。要理解它，先回忆 Transformer 生成文字时发生了什么。假设模型已经读了 10 万个 token，现在要生成第 100001 个 token，它需要回头注意前面大量内容。为了不把过去每个 token 的注意力信息重新计算一遍，模型会保存过去每个 token 的 Key 和 Value，这就是 KV cache。上下文越长、模型 attention heads 越多，这个缓存就越巨大。于是推理时常常不是“算力不够”，而是“显存被历史笔记塞满了”。论文明确说，传统 Multi-Head Attention 的 KV cache 是 LLM 推理效率的重要瓶颈。([arXiv][2])

MLA 的想法非常像压缩文件。普通 Multi-Head Attention 对每个历史 token 保存完整的 K 和 V，就像你上了一百节课，每节课都保存完整高清录像。MLA 则先把 K 和 V 联合压缩成一个更小的 latent vector，也就是“潜在表示”，推理时主要缓存这个压缩后的东西，需要计算注意力时再通过投影恢复需要的信息。论文把它叫做 **low-rank key-value joint compression**。([arXiv][2]) 也就是说，它不是简单粗暴地说“少保存几个 attention head”，而是在问：这些 Key、Value 信息里是不是有大量冗余？能不能先压缩成低维空间，再从这个紧凑表示完成后续计算？最终 DeepSeek-V2 报告，与 DeepSeek 67B 相比，KV cache 减少了 **93.3%**，而最大生成吞吐提高到 **5.76 倍**。([arXiv][1]) 这是非常巨大的工程收益。

## 06 · 解耦 RoPE：分开内容与位置

这里还有一个容易忽略的小麻烦：位置编码。Transformer 不光要知道“某个词是什么”，还要知道“它出现在第几个位置”。DeepSeek-V2 原本想继续使用 RoPE，也就是 Rotary Position Embedding，但 RoPE 如果直接作用在被压缩的 Key 上，会让那个低秩压缩结构和具体位置纠缠在一起，结果原来能提前合并的矩阵不能合并，推理时甚至可能需要重新计算过去 token 的 Key，等于把 MLA 的效率优势破坏掉。于是作者提出 **decoupled RoPE**：把“内容信息”和“位置信息”部分拆开，让压缩的 Key/Value 负责主要内容表示，再用额外的小型 query/key 分支承载 RoPE。([arXiv][2]) 可以把它想成压缩一本书的时候，不把“第几页”直接烙死在压缩内容里，而是另外保存一个很轻量的页码索引。这样内容可以高效压缩，位置信息又不会丢。

## 07 · 小缓存与强能力能否兼得

为什么 MLA 很重要？因为此前也有 MQA 和 GQA 这类方法尝试减少 KV cache，但通常要牺牲一部分表现。DeepSeek-V2 的目标不是单纯“缓存越小越好”，而是试图得到两边的好处：**接近甚至超过标准 MHA 的能力，同时得到非常小的 KV cache。**论文的比较里，MLA 的缓存规模大约相当于只有 2.25 个 group 的 GQA，但作者的消融实验显示其性能能优于标准 MHA。([arXiv][2]) 所以 MLA 不是“压缩一下显存”这么简单，而是在重新设计 attention 的信息表示方式：**不是保存完整历史，而是保存历史的紧凑潜在表示。**后来 DeepSeek-V3 继续沿用 MLA，也说明这个设计成为了 DeepSeek 架构路线中的核心部件。

## 08 · 数据质量与训练效率

数据方面，DeepSeek-V2 在 **8.1 万亿 token** 的高质量、多来源语料上进行预训练，而且作者特别提到相较之前 DeepSeek 67B，增加了更多中文数据，并改善了数据质量。([arXiv][2]) 这里很值得和你前面读的 GPT 系列对应起来：GPT-2 的一个大突破是意识到“数据的多样性本身就是任务的多样性”，GPT-3 进一步扩大规模，而 DeepSeek-V2 时代已经进入另一个阶段——模型规模和数据规模很大以后，不只是“多喂数据”，而要同时关心**数据质量、语言分布、模型架构和单位 token 的训练成本**。换句话说，早期 scaling 更像“多就是好”，这一时期则越来越像“同样 1 万亿 token，我怎样把每一个 token 的价值榨得更高”。

## 09 · SFT：学习怎样当助手

预训练以后，DeepSeek-V2 也没有直接拿出来聊天。作者收集了约 **150 万个多轮对话会话**，覆盖数学、代码、写作、推理、安全等领域，用它们进行 SFT，也就是 supervised fine-tuning。([arXiv][2]) 你可以把预训练想成“读完大学以前的所有书”，SFT 则像“开始学习怎么当一个助手”：别人问问题的时候怎么组织答案、怎样遵循指令、怎样输出合适格式。这里和 GPT-4 的逻辑很相似：预训练主要把“能力”长出来，后训练更多负责告诉模型“怎样使用这些能力”。

## 10 · GRPO：用组内比较学习

然后是非常值得注意的 **GRPO，Group Relative Policy Optimization**。如果你刚才读过 DeepSeek-V3，我已经讲过它，但 V2 正是这条路线的重要来源之一。传统 PPO 式 RLHF 往往需要额外训练一个 value model，也就是 critic，估计某个回答究竟比预期好多少。大模型时代这很贵，因为你等于除了主模型，还要再养一个很大的评估模型。GRPO 的核心想法是：对同一个问题一次生成一组答案，然后让这些答案在组内比较，相对好的提高概率，相对差的降低概率，从而不再依赖一个同规模的 critic。([arXiv][2]) 费曼式地说，传统做法像每次考试都请一个专门老师预测“这名学生正常情况下应该考多少分”；GRPO 更像把同一道题交给 8 个学生，直接比较这 8 份答案谁更好，然后根据相对名次调整。这样训练强化学习模型会省很多资源。

## 11 · 对齐也有代价

这里还有一个很值得思考的现象，论文称为 **alignment tax**。对模型进行 SFT 和 RL 后，它会更符合人类偏好、更会聊天，但某些纯 benchmark 能力可能出现轻微下降。([arXiv][2]) 这个概念和 GPT-4 技术报告里你看到的“RLHF 会改变 calibration”等现象非常一致：后训练不是免费的万能增强，它更像重新调整模型的行为分布。你把“更有帮助、更会遵循指令、更安全”这些目标提高权重，有时会轻微牺牲原始模型某些能力。所以**能力和对齐不是同一个指标**，甚至有时会发生 trade-off。

## 12 · 模型能力与长上下文

再看模型最终到底强不强。论文的重点并不是说 DeepSeek-V2 在所有 benchmark 上全面击败闭源顶级模型，而是强调它在**只激活 21B 参数**的情况下，达到了当时开源模型中的第一梯队表现。论文在 MMLU、BBH、GSM8K、HumanEval、中文 C-Eval、CMMLU 等很多测试上进行了比较，作者把 DeepSeek-V2 定位为当时最强的开源 MoE 模型之一。聊天版本经过 RL 后，在 AlpacaEval 2.0 获得 38.9 的 length-controlled win rate，MT-Bench 达到 8.97；中文 AlignBench 为 7.91，并在当时作者测试的开源模型中领先。([arXiv][2]) 真正值得注意的不是某个数字，而是它做到这些时每个 token 的有效计算规模只有 21B。

DeepSeek-V2 还支持 **128K context length**。([arXiv][1]) 这跟 MLA 是紧密相关的，因为上下文变长以后，KV cache 原本会线性增长，如果不解决缓存问题，你理论上支持 128K，实际部署时却可能因为显存太贵根本跑不起来。这里可以看到很典型的“共同设计”：不是先宣布“我要 128K”，再想办法硬塞进去；而是 attention 结构本身就为长上下文推理做了优化。大模型真正做到可用，很多时候就是这种算法和部署需求一起反推架构。

## 13 · 三个效率数字背后的设计

然后来看论文最想强调的一组效率数字。和 DeepSeek 67B dense 模型相比，DeepSeek-V2 报告：训练成本减少 **42.5%**，KV cache 减少 **93.3%**，最大生成吞吐提高至 **5.76 倍**。([arXiv][1]) 这三个数字分别对应三层问题：MoE 解决“训练每个 token 要激活多少参数”；MLA 解决“推理时每个历史 token 要存多少东西”；整个系统设计解决“同样机器一秒究竟能生成多少 token”。所以论文标题里的 strong、economical、efficient 不是三个同义词：**strong 是能力，economical 更偏训练成本，efficient 更偏推理效率。**

## 14 · V2 到 V3 的继承与演化

如果你已经读过 DeepSeek-V3，现在再看 V2，就能很清楚看到 V3 的继承关系。V2 已经有 **MLA + DeepSeekMoE + GRPO + 长上下文**；V3 继续扩大模型和数据规模，又加入更激进的 FP8 训练、auxiliary-loss-free load balancing、multi-token prediction、更复杂的通信和流水线优化。也就是说，**DeepSeek-V2 更像确定了“架构方向”，DeepSeek-V3 更像证明这条方向可以扩展到更大的规模，并把系统工程做到极致。**尤其值得注意的是 V2 还主要使用传统辅助负载均衡损失，而 V3 后来进一步提出 auxiliary-loss-free balancing，这正是一个很典型的“上一代发现问题，下一代把它拆掉”的演化。

## 15 · 从智能的来源到运行成本

现在把 DeepSeek-V2 放回你已经读过的整个历史里，会看到研究问题已经从“智能从哪里来”逐渐转向“智能怎样便宜地运行”。GPT-1 解决的是：**无监督语言模型预训练能不能产生可迁移能力？**GPT-2 问：**只做语言建模，会不会自然学出多个任务？**GPT-3 问：**规模足够大以后，能不能靠上下文直接指定任务，而不改参数？**GPT-4 展示：**这种通用模型可以扩展到非常广的专业能力和多模态输入，同时安全与对齐越来越重要。**DeepSeek-V2 开始非常明确地问：**既然我们已经知道大模型越做越强，那么能不能不用每一个 token 都支付“大模型的全价”？**它的核心答案就是 MoE + MLA。

这里我认为有一个特别值得你真正理解，而不是背概念的思想：**MoE 和 MLA其实解决的是两种完全不同的“浪费”。**MoE 认为模型参数里存在“计算浪费”：一个代码 token 没必要动用所有专家，所以只激活一小部分参数；MLA 认为 attention 历史里存在“存储浪费”：过去每个 token 的完整 K/V 信息没必要全保存，所以把它压缩成 latent representation。一个在压缩“当前计算”，一个在压缩“过去记忆”。把两者组合起来，就是 DeepSeek-V2 的架构逻辑：**大脑可以非常大，但每次思考只叫少数神经区域工作；记忆可以非常长，但不要把所有历史原样存下来。**

## 16 · 用一分钟讲给朋友听

如果现在合上这篇论文，用一分钟给完全不懂 AI 的朋友解释，我会这样说：**DeepSeek-V2 想解决的问题不是单纯把语言模型做得更大，而是怎样让一个很大的模型运行得便宜。它一共有 2360 亿参数，但用了 MoE，所以每处理一个 token 只激活约 210 亿参数；它还把专家切得更细，并保留共享专家，让不同专家更容易专业化。另一方面，传统 Transformer 在长文本生成时要保存巨大的 KV cache，DeepSeek-V2 提出了 MLA，把 Key 和 Value 压缩成一个小得多的 latent vector，结果 KV cache 相比上一代减少约 93.3%。在 8.1 万亿 token 上预训练以后，它又通过 150 万左右对话做 SFT，并用 GRPO 做强化学习。最终，它用相对少的激活参数取得了当时开源模型中的顶级能力，同时显著减少训练和推理成本。**([arXiv][1])

所以如果要给这篇论文留一句最值得记住的话，我会写：**DeepSeek-V2 = Sparse computation + Compressed memory。**也就是：**MoE 让“大模型不必每一步都全脑运转”，MLA 让“长记忆不必原封不动全部保存”。**📖 如果说 GPT 系列前几篇论文主要在探索“怎样让模型获得越来越通用的智能”，那么 DeepSeek-V2 开始把另一个问题推到舞台中央：**真正能大规模部署的智能，不只是要强，还必须让每一个 token 足够便宜。**而你刚才读的 DeepSeek-V3，本质上就是沿着 V2 这句话继续往前推了一大步。
